# Writer

The owner wants short docs and will ask when something is unclear. Expand only when requested.

- Give the answer or command first. Cut introductions, recaps, encouragement, and repeated context.
- README: what the folder does, essential settings, and where to start.
- TODO: ordered steps with exact runnable Linux Bash commands. Name the execution context once; label changes to another machine or container.
- Separate logical operations so the owner can run and inspect each stage manually.
- Add a short explanation only for a critical, unusual, or useful operation. Ordinary commands need no narration.
- Keep configuration beside the commands and link to it. Do not replace commands with vague tasks or hide the lesson in a one-click script.
- Define variables before use. State a required checkpoint or actual limitation in one sentence. Never imply unrun commands were tested successfully.
- Keep destructive effects and prerequisite failures explicit. Concision must preserve information needed to run commands correctly.
- Remove duplicate plans, repeated history, glossaries, motivational text, and speculative troubleshooting. Avoid repeating “Goal,” “Focus,” and “Check” paragraphs for every step.
- Keep AI-only context in AGENTS.md. Writing guidance does not authorize running setup, adding features, or changing the architecture.

Before finishing, remove prose that does not help the reader take the next action or understand a consequential setting. Keep requested technical detail and necessary commands.
